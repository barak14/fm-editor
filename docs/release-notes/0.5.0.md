# FM Editor 0.5.0 — preview notes

Unsigned experimental preview for Windows x64 and Linux x64 (Proton). Back up
saves and use offline single-player saves only.

## Changes since 0.4.3

- **FM24 Epic** (24.4.2+2081827) is a recorded build. It uses the FM24 Steam
  schema with the Epic `fm.exe` fingerprint. A contributor on a Windows Epic
  install matched two players' attributes and one club's transfer budget in
  game, and confirmed and restored one attribute edit and one budget edit.
  Other fields are inherited from Steam and have not been checked on Epic.
- **FM27 PC Game Pass 27.1** (Store package 0.9.2524.0) is a recorded build.
  Its addresses came from the new module scan and were checked by decoding the
  real birth dates of three players and three staff. A write and Undo has not
  yet been confirmed in FM on this package.
- **Builds are matched by fingerprint, not folder.** An install in an unusual
  location (Heroic, a custom folder) still selects its recorded build.
- **Unrecognised builds no longer get refused outright.** For a build of
  FM24, FM26 or FM27 with no recorded fingerprint (FM27 Steam, for example, or
  a game update), the editor tries the release's recorded addresses. It then
  decodes sample players, staff and clubs before showing anything. If the check
  passes, the editor attaches with an amber version label and a "back up your
  save" warning. If it fails, the attachment is refused with the failed check
  named.
- **Moved addresses are scanned for.** If none of the recorded addresses fit,
  the editor scans the game module for the player, staff and club arrays (and,
  on FM27, the manager, player-coach and finance classes), then runs the same
  check. A build opened this way is **read-only** and labelled "read-only:
  detected addresses". The found addresses are written to the game-detection
  log; include them in a bug report so the build can be recorded.
- Before every write, on all builds, the editor confirms the same save is still
  loaded. Reloading or quitting the save clears Undo and reruns the check.

## Fixes

- If an unrecognised build never shows a save, the status line says so after
  20 seconds instead of waiting silently.
- **File → Load Save** no longer hangs at "Loading save… 0%" when no save is
  connected.
- Linux builds compile with Rust 1.100 (`rfd` updated to 0.18).

## Tested here

- FM24 Steam forced through the validation path: check passed, amber label,
  one edit and Undo, check rerun after reloading the save.
- Forced module scans on FM24 Steam and FM26 Steam reproduced their recorded
  addresses in under 0.1 s.
- FM27 Game Pass 27.1: scan found the arrays and classes, and the check passed.

## Known limits

- FM27 Steam has no recorded fingerprint, so it always goes through the check
  and shows the amber label.
- Builds opened with scanned addresses are read-only until they are recorded.
- On Game Pass, club finances, stadium, club membership / My clubs and club
  policy remain disabled or unverified.
- Unknown releases (for example FM28) are refused.
