# FM Editor 0.4.1 — draft preview notes

Status: source preparation only. No 0.4.1 tag, published release or verified native
installer is established by this document. CI results and artifact identity must
be checked for the exact candidate commit before sharing a download.

## Changes since 0.4.0

- Identify the FM release from the game module's PE product metadata instead of
  relying primarily on its installation folder. FM24 reads `fm.exe`; FM26/FM27
  read `game_plugin.dll`, since their EXE can describe the Unity engine instead.
- Retain recognised installation-directory names as a fallback, including compact
  `FootballManager24` names. Unsupported/conflicting FM product identities fail
  explicitly rather than being overridden by the directory.
- Save build-detection reports containing PID, discovered module paths/base/size,
  product and file versions, discovery/resource errors, identification source,
  storefront hints and schema-selection outcome. Reports are process-local;
  an absent optional plugin is not presented as a discovered FM27 DLL.
- Record unsupported processes even when another running FM can be identified.
  When none can be identified, retain every candidate's failure context.
- Persist reports in a bounded rotating log, with duplicate suppression and
  coordination between editor processes. Log-write failures do not block attach.

## Compatibility limits

**This is not Epic support.** Recognised Epic installations are identified as
Epic and rejected because no verified Epic schema exists. The diagnostic retest
is intended to collect evidence, not enable editing. Moved/custom installs still
have limitations in storefront detection; metadata identifies the release, not
whether its offsets are compatible.

No memory offsets or write behaviour changed. The existing fingerprint gate is
preserved. FM27 Game Pass remains unverified. The installer and Arch package pins
still describe 0.4.0; they must not be presented as 0.4.1 downloads.

## Requesting a retest

After both **Build and package** jobs pass for the candidate commit, share the
run's Windows portable artifact (`fm-editor-x86_64-pc-windows-msvc`) with the
reporter. Actions artifact downloads require GitHub sign-in and expire after 14
days; a public release download is a separate publication step.

Suggested GitHub reply (insert the successful run URL and candidate commit):

> Please try the 0.4.1 diagnostic build from **[successful run URL]**, source commit
> **[candidate commit]**. Download `fm-editor-x86_64-pc-windows-msvc`, extract the
> Actions artifact and then the portable ZIP inside it into a new folder. Check
> `BUILD-INFO.json`: it should say `0.4.1` and the commit above. Close the previous
> editor and run this folder's `fm-editor.exe` while your Epic FM24 game is running
> with a save loaded. Leave Auto-connect enabled, or use Load Game to attempt
> detection. We do not expect Epic editing to work yet; an unsupported-build
> message is useful evidence too. Please do not attempt any edits.
>
> After the attempt, open `%LOCALAPPDATA%\fm-editor\logs` (paste that path into
> Explorer's address bar). Attach `game-detection.log` and, if present,
> `game-detection.log.1`, plus the error text and the full FM build number from
> Game Status. These logs contain installation paths that may include your Windows
> account name; review/redact personal path components before sharing. Please
> preserve version strings, module filenames and the rest of the diagnostic data.
> You do not need to send your save, memory dumps or the game executable.

On Linux, the corresponding log is
`${XDG_DATA_HOME:-$HOME/.local/share}/fm-editor/logs/game-detection.log`.
Each log is limited to 512 KiB with one backup; individual reports have a 32 KiB
body limit and an explicit truncation marker. Repeated identical reports for the
same PID are suppressed. The auxiliary `.lock` file is not a report to upload.

## Evidence and remaining gates

Feature verification before version preparation:

- Local Rust checks and tests: 254 passed; three installed-file/manual tests were
  ignored by the default suite.
- Windows GNU cross-check, not Windows runtime verification.
- File-only metadata identification against installed Steam FM24
  `24.4.2+2081827` and FM27 plugin `27.0.0+2493426`, including persistent JSONL
  output. No game-memory writes were performed.
- Linux disconnected GUI build/launch smoke test.

Still required for publication: successful native Windows/Linux CI at the exact
0.4.1 source commit; review of extracted portable packages and their matching
source/checksums; supported-build live attach/edit/Undo evidence; and dependency
licence/source review, including `pelite` and its new transitive dependencies.
Epic metadata and offsets are not locally verified. See the
[release procedure](../releases.md#preparing-041) for the full sequence.
